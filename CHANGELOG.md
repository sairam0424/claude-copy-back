## [0.1.1] - 2026-10-25

The matcher now models how Claude Code draws links and struck text in the terminals that draw them label-only (Warp, and by a static read many others) as well as in the default drawing, the toast is shorter, the tests no longer depend on the clock, and CI is leaner and watches new Claude Code versions. Still experimental and macOS only. Checked by unit tests, engine tests, the sealed capture rig and a counted sealed live pass of `/cc` itself on Claude Code 2.1.310 (reported; see Known limitations for what it does not show).

### Added
- The matcher accepts both ways Claude Code draws links and struck text (`src/core/drawing.ts`, `links.ts`, `ordinals.ts`). Claude Code picks one drawing by the terminal it detects: a link shown as its label only with struck text drawn without tildes (the rig saw this with Warp, and once with iTerm; a static read of 2.1.310 by a review lists many more terminals), or a link shown as `label (url)` with the tildes kept (no terminal name set; Terminal.app is expected to behave so), and a setting or an environment variable can force either. `/cc` cannot know which applies, so it searches all four combinations. Also modelled now: a link title drawn after the destination, the letter and roman-numeral markers of nested ordered lists, a line break inside a code span drawn as a space, and a rule that uses the copy's own line breaks to tell a message from its near-copy.
- Rig: `--profile default|warp` (adds only `TERM_PROGRAM=WarpTerminal`, a Warp version string and `COLORTERM=truecolor`); a synthetic corpus with inline markup inside list items, headings and quotes, links, strikethrough, nested ordered lists, wide characters and repeated phrases (family C); a pass rule written and hashed before any of its screens existed (`realrender/RULE-3.md`); and the tools `freeze.mjs`, `rescore.mjs`, `tokenfree.mjs` and `modeldiff.mjs --hunks`.
- The never-guess gate: `node realrender/tokenfree.mjs --set DIR --gate yes` exits 1 on any wrong or picked-wrong answer to a copy of the words between two tokens, or on a set too small to mean anything. Rule 3 judges drawing fidelity only and would pass a matcher that guesses (every copy of it holds a unique token), so the gate is a release step (`docs/DEVELOPMENT.md`).
- `CONTRIBUTING.md`, a feature request form and `CODEOWNERS`.
- CI: a `ci-ok` check that a branch rule can require; `engine-drift.yml`, a weekly run of the strict validate, the footprint gate and the kit tests against the newest published Claude Code; and `claude plugin test .` in the engine job.
- Tests: 1540 matcher, `/cc`, manifest and workflow tests in 53 files, 87 tests on the engine's kit in 6 files, and 398 rig unit tests in 44 files.

### Changed
- The source guard refuses more ways to reach a global without naming it: property-descriptor and `defineProperty` calls, any `prototype`, a destructured `constructor`, the strings `"constructor"`, `"prototype"` and `"__proto__"` wherever they stand, and a member or destructured key named by a string built at run time. The test spies on the console, the standard streams and `fetch` are default-deny: a call is innocent only when its stack shows Node's own streams or test runner, so a call from a promise job or a short timer counts, and so does an encoded copy of the clipboard. A review had printed the code points of the clipboard from a promise job and every layer stayed green.
- The toast no longer repeats the plugin name (Claude Code puts `copy-back:` in front of it) and every line fits 45 characters, so the reply number stays visible at 60 columns. `characters` became `chars`, for example `copied 182 chars from reply 1 (1 = newest)`. The 45 came from earlier sealed screens; in the counted live pass on 2.1.310 all 283 toasts of the new wording were shown whole, the longest row (56 characters) at 60 columns (reported).
- The 200,000 character clipboard limit counts characters, not UTF-16 units: 100,001 emoji used to be refused.
- CI runs on every pull request on Linux only (Node 22.19.0, 24.x and 26.x); the macOS legs and the rig's unit tests run on pushes to `main` and manual runs. The engine job pins Claude Code 2.1.299 and 2.1.310 (it was 2.1.299 and 2.1.309).
- The node:test files are named `*.test.mts`.

### Fixed
- `claude plugin test .` at the repository root passes (87 of 87); it used to run the node:test files too and fail.
- Tests that bound time no longer fail when the machine is busy: each asserts the answer first and then CPU time against a generous bound, and `CB_TEST_TIME_FACTOR` relaxes every bound.
- The toast prints only reason words from the fixed list; an unknown reason reads as the catch-all line.
- Rig: a capture file without a log line, a log line without a file or an overwritten write now fails the launch; the first attempt of a retried case is kept and scored; `freeze.json` records how its tree digest is computed.
- Rig: the read of the real clipboard (a hash of `pbpaste`) runs under `pipefail`, so a failing `pbpaste` can no longer read as an empty clipboard; both hashes of the live pass were the hash of empty input.
- The `ci-ok` decision script is run by a test on sample results (two mutants of it had survived the checks that read the workflow as text).
- Docs: Node coverage (CI runs 22.19.0, 24.x and 26.x; locally 22.23.2 and 26.9.0), file and test counts, stale test-command comments, which terminals draw links label-only, the list of drawings that are not modelled, "no network access" (the mod calls no network API; the guard is a tripwire), what the privacy spies see, and what the clipboard hashes of the rig can show.

### Known limitations
- Reported, not re-runnable from this repository: in the sealed rig on Claude Code 2.1.310 (classic display, synthetic content), a window drawn the Warp way scored 240 of 240 copies exact, 0 wrong slices and 0 false positives, and a window drawn the default way scored 240 of 240 as well; the 0.1.0 matcher scored 178 of 240 on the Warp window. The copies are still built by a model of a terminal selection, so this shows how Claude Code draws in Warp, not what Warp copies. Warp's selection and copy, the real `pbpaste` and `pbcopy`, the fullscreen display and the 20-real-copy test in `CAPTURES.md` remain unverified.
- A counted live pass of `/cc` on this build ran on Claude Code 2.1.310 (classic display, synthetic content; reported, evidence not published): 12 of 12 conditions. In the Warp drawing 160 of 160 copies were exact (links 11 of 11, struck text 11 of 11) and 32 of 32 refusals left the clipboard untouched; in the default drawing 40 of 40 and 8 of 8; no wrong payload and no wrong toast in 283 cases; no model request; no non-local socket in 8,658 samples. Its limits: its rule (rule 3, revision 2) is kept outside this repository; the Warp set was rebuilt from the spans the screen shows because link destinations are not drawn; the default drawing was exercised at one width only; the check of the real clipboard was two hash reads around a clipboard-writing stand-in for the plugin, not the real plugin, and both hashes were the hash of empty input, so it shows only that no text appeared; and the copies came from a model of a terminal selection, through stand-ins for `pbpaste` and `pbcopy`. Not shown: Warp's own selection and copy, the real `pbpaste` and `pbcopy`, the fullscreen display, other Claude Code versions in a live pass.
- Drawings the matcher does not model, expected to be refused. Known so far: `[](url)` and `![](url)` (empty label or alt text), `<mailto:a@b>`, a bare `www.` address in the drawing that shows `label (url)`, `&nbsp;` (the screen shows a no-break space), a zero-width space (U+200B) inside a word (the screen drops it, possibly in tmux and not in Claude Code), a link inside a link label (`[a [b](u1) c](u2)`), a line or list item that starts with `~~~` or `~~~~` followed by text (the matcher reads a code fence), `~~x~~~` next to a link, a nested ordered list that starts at a number other than 1 directly under its parent line, and an ordered list that starts at 0 or a depth-2 list that starts at 3999 (the screen draws numerals for the whole list). **Other constructs may also be refused.** A review sweep of the real engine (432 random messages compared, 576 judged; reported, evidence not published) found each of these as a refusal and none as a wrong slice, but that is not a proof that none can give one.
- Because the terminal is unknown, a copy that also fits another message under the other drawing is refused as ambiguous.
- Cost grows with the size of the replies, and a reply that holds both a link and struck text is searched under four drawings: about four times the 0.1.0 cost on such input (a synthetic window of 40 replies and 40 MB took 29.6 s and 1.67 GB, against 7.5 s and 601 MB on 0.1.0; reported, not re-runnable from this repository). Real replies are far smaller. The earlier wording that the search is bounded in memory and time whatever the replies hold is withdrawn.
- The other limitations of 0.1.0 still hold: macOS only; tables, diffs and tool output are not matched; at least 12 characters and the newest 40 replies; the 2 second clipboard read can refuse on a heavily loaded machine; installing from the repository installs the whole folder.

## [0.1.0] - 2026-10-24

First release. Experimental: verified in a sealed rig against a synthetic session, not yet on a real Warp session or with the real `pbpaste` and `pbcopy`. macOS only.

### Added
- The `/cc` command. After you copy text out of the terminal, `/cc` reads the clipboard once (`pbpaste`, 2 second limit, UTF-8 locale), finds that text in the newest 40 assistant replies of the session, and writes Claude's own text for it back with the engine's clipboard call. It is an immediate command, answers `{}` (nothing reaches the model), keeps no state and shows one counts-only toast. Every refusal (empty, unreadable or over 200,000 characters, session unreadable, under 12 characters, no match, ambiguous) leaves the clipboard as it was.
- The lossless matcher (`src/core`). It models how Claude Code draws a reply (two-column margin, reply marker, `-` bullets, hanging list text, wrap at the terminal width, code, quotes, links, numbering) so that it can search the drawn text and map each hit back to the reply's markdown. The answer is an exact slice of what Claude wrote; the paste form drops the list or quote prefix from later lines and restores the first line's indentation. When the same words sit in several places and Claude's original text differs between them, the copy's indentation is tried first, and then it refuses instead of taking the newest; identical original text is one answer, and the toast names the newest reply that holds it. The search is bounded in memory and time.
- The engine seam and the footprint gate. Every engine call goes through four wrappers in `hooks/api.ts`; `scripts/check-footprint.sh` pins the access report to exactly five APIs (`$.command.register`, `$.process.run` via `pbpaste`, `$.session.messages`, `$.ui.copy`, `$.ui.toast`), no truncation marker, a `calls` line of 130 characters against a gate of 850, no gating hook and no state.
- Privacy guards for what the access report cannot see: a source scan of everything the hooks load (`scripts/check-sources.mjs`), a type check where `console`, `process` and `fetch` are unknown names (`scripts/typecheck.sh`), spies on the console, the standard streams and `fetch` in the tests, and a toast built from counts and fixed words only.
- The offline replay harness and screen simulator (`src/sim`, `src/replay`, `scripts/replay.mjs`).
- The captures tool (`scripts/captures.mjs`, `CAPTURES.md`): a real-copy acceptance test of about 20 of your own copies with a frozen pass rule (at least 20 judged, 70 percent right, at least 10 matched and right, nothing dangerous). It prints counts only; `run --show` prints your own text and only to a terminal.
- The sealed live-test rig (`realrender/`): the real Claude Code on a synthetic session inside a Seatbelt profile, with stand-ins for `pbpaste` and `pbcopy`, a local stub for the API, sandbox controls and two frozen pass rules.
- Tests: 1325 matcher, `/cc` and manifest tests in 46 files, 87 tests on the engine's kit in 6 files, and 263 rig unit tests in 35 files.
- A plugin manifest and a marketplace entry (`copy-back@claude-copy-back`), the MIT license, a CI workflow (plain tests on Linux and macOS, source guard, shellcheck, and the engine gates on a pinned Claude Code), Dependabot for GitHub Actions, a bug report form and a pull request template, and the documentation: `README.md`, `SECURITY.md`, `AGENTS.md`, `CAPTURES.md` and `docs/DEVELOPMENT.md`.

### Known limitations
- macOS only: the mod starts `pbpaste`. Linux and Windows are not supported and were not tested.
- Verified only in the sealed rig, against a synthetic session, on Claude Code 2.1.309, classic display only (counted pass: 160 of 160 exact, 32 of 32 refusals untouched, no model request, no non-local socket) with sanity launches on 2.1.310. The copies in that pass were built by a model of a terminal selection from real Claude Code screens and fed through a `pbpaste` stand-in, so the pass does not show what Warp or any other terminal puts on the clipboard. It was run, reviewed and re-scored by the author with separate Claude sessions (the model was not recorded); the raw evidence is not published. **Not verified:** Warp or any real terminal's clipboard, the real `pbpaste` and `pbcopy`, Claude Code's fullscreen display (where Claude Code takes over the mouse and selecting may need a modifier key), an organisation policy that refuses a mod starting a program, other Claude Code versions, typing `/cc` while a reply is streaming, and the 20-real-copy test in `CAPTURES.md`.
- Tables, diffs and tool output are not matched; they are refused.
- Links and struck-through text are drawn differently by Claude Code depending on the terminal. The matcher was calibrated on a run with no terminal name set; in Warp such copies are expected to be refused, not mis-matched. Real replies contain many links and the synthetic test replies few, so expect `no match` whenever a copy includes a link label or struck text; the test figure (of 160 synthetic copies edited to that style only 4 changed, all 4 became `no match`) is thin evidence and not a refusal rate.
- A copy needs at least 12 characters after folding and must be in the newest 40 replies. A selection that runs from one reply into the next is expected to be refused (one example was checked against the matcher, none live).
- The 2 second clipboard read limit can refuse with `could not read the clipboard` on a heavily loaded machine (3 of 80 copies in two sanity launches). It never wrote wrong text; type `/cc` again.
- Claude Code may prefix the toast with the mod's name as well, so it can read `copy-back: copy-back: copied ...`.
- Installing from the repository installs the whole folder, including `src/captures`, a tool for the maintainer's own testing that the plugin never loads.
- `tests/budget.test.ts` and six other test files assert wall-clock time and can fail under heavy load; rerun them alone.
- Development needs Node 22.19 or newer by the Node changelog; locally the suite has only been run on Node 26.9.0 (CI is set up to run the floor and 24.x on Linux and macOS and 26.x on Linux).
